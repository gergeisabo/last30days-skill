Grok session expiry is now detected locally by parsing `expires_at` from `~/.grok/auth.json`. Expired sessions are **skipped** at research time (not attempted) because a revoked refresh triggers grok to delete `auth.json` — a credential-store wipe is worse than skipping. Doctor reports expired grok as **error** (configured-but-broken) so collect-then-pick selects a fallback backend instead. When a fallback backend fully serves the request after the primary auth-failed, the source status is now **ok** (not PARTIAL or AUTH_FAILED) with informational detail about the fallback path. SKILL.md guidance updated: hosts should say "Grok session expired; X was served via browser cookies" instead of "Grok CLI is not signed in" which misrepresents the history.
